# Fusion API verification

Method: each member below was looked up on the official reference
(`https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/<namespace>_<Class>_<member>.htm`, page footer "© 2026 Autodesk")
on 2026-10-20. **VERIFIED-DOC** = member exists with the semantics used. **ASSUMPTION** = documented member, but our
*interpretation* of the geometry/behaviour is untested in real Fusion. **UNDOCUMENTED** = could not be confirmed.
Nothing here has been executed inside Fusion yet; `tests/fake_adsk.py` only exercises our own logic.

## Defects found and fixed (all in the first Phase 1 draft)
| Draft code | Problem | Fix |
|---|---|---|
| `commandDefinitions.addButtonCommand(...)` | **Does not exist** (would crash startup) | `addButtonDefinition(id, name, tooltip[, resourceFolder])` |
| `app.openExternalWebBrowser(url)` | not in the API reference | Python `webbrowser.open` (https only) |
| `design.activeSheetMetalRule` (probed) | property is on `Component`, not `Design` | `body.parentComponent.activeSheetMetalRule` |
| `flatPattern.flatBodies` (probed) | does not exist; `FlatPattern.flatBody` does | `comp.flatPattern.flatBody` |
| `getattr(..., "isSheetMetal")` probing | `BRepBody.isSheetMetal` is documented | used directly; non-sheet-metal bodies are rejected with a clear message |
| thickness geometry fallback relied on face-normal sign | sign convention depends on `BRepFace.isParamReversed`, not guaranteed | orientation-agnostic parallel-plane distance, used only as fallback/cross-check |
| hole = cylinder with exactly 2 edges | a seam edge may exist | tolerate a straight edge of length ≈ thickness |
| `HTMLEventHandler`/palette path as raw OS path | `htmlFileURL` is a *URL* | `Path.as_uri()` (file:///…) – see ASSUMPTION below |
| stale modules after add-in stop/re-run | Fusion keeps one interpreter | modules purged from `sys.modules` in `stop()` |
| no diagnostics | | rotating log, face census, panel-id dump, per-event log lines |

**ASSUMPTION (documented members, unverified behaviour)** – check with the smoke test / log:
1. `activeSheetMetalRule.thickness.value` equals the modelled thickness (cross-checked against geometry; mismatch is warned).
2. A through-hole's cylindrical face is one face bounded by two full `Circle3D` edges (± seam line).
3. A bend is two coaxial cylinders (inner/outer) whose straight edges lie along the axis; arcs are `Arc3D`.
4. `BRepEdge.faces` returns exactly the two adjacent faces, and `tempId` is stable within one analysis.
5. `Palettes.add` accepts a `file:///` URL for local HTML; the CEF page exposes `adsk.fusionSendData`.
6. `flatPattern.flatBody.boundingBox` is the flat size (axis-aligned; may overstate a rotated pattern).
7. Both faces beside a bend are reported as "flanges" (base and upright), each with length from the tangent line.

**UNDOCUMENTED / NOT CONFIRMED**
- Toolbar panel id `SolidScriptsAddinsPanel`: panel ids are not listed in the reference. If absent, the add-in logs every panel id
  and opens the palette directly instead of failing.
- `.manifest` field set (`autodeskProduct, type, id, author, description, version, runOnStartup, supportedOS, editEnabled`): the
  manifest reference page was not retrievable; fields follow what Fusion's own "Create add-in" generates. Compare with a manifest
  generated by Fusion if the add-in does not appear in the Add-Ins list.
- Not used (but available and possibly better): `FlatPattern.getBendInfo(bendEdge)` (since Oct 2022) returns bend angle from flat-pattern bend lines.

Install locations (official "Using Samples from GitHub" page): Windows `%appdata%\Autodesk\Autodesk Fusion\API\AddIns` and `...\Scripts`;
macOS `~/Library/Application Support/Autodesk/Autodesk Fusion/API/AddIns`; the folder name must equal the `.manifest` name.
